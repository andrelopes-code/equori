# Web Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the card screens of the web track (statements, payments, financing, installment purchases, refunds, disputes, cancellation, anticipation, card settings) and the four read or write endpoints they need.

**Architecture:** Four backend tasks (B1–B4) come first in the `ledger` module. The web part adds `web/src/features/cards/`, which consumes `features/accounts` and `features/transactions` through their `index.ts`; `app/router.tsx` composes the card routes, the `/accounts/$id` redirect and the card panel on the transaction detail. Pure logic (grouping, signs, integer arithmetic, field paths) lands in one task before the screens.

**Tech Stack:** Go 1.27, sqlc, oapi-codegen; the web stack of sub-project 1 unchanged (React 19.3.1, TanStack Router 1.170.41, TanStack Query 5.104.1, Slotted `0.1.0-beta.2`, Vitest 5.0.5, Testing Library). No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-18-web-cards-design.md` (C1–C23, Routes, Phone ergonomics, Data, Problem codes, Backend gaps, Tests). Inherited: `docs/superpowers/specs/2026-10-17-web-foundation-ledger-design.md`, `docs/superpowers/plans/2026-10-17-web-ledger.md` (Global Constraints apply unchanged).

**Start condition:** sub-project 1 Tasks 15–19 are committed. Task 6 onward relies on `AccountPage` at `/accounts/$id`, `balanceQuery` in `features/accounts/api.ts` (sub-project 1 Task 16) and `web/src/app/routes-responsive.test.tsx` (sub-project 1 Task 19).

## Review Focus

1. A card account without a credit limit shows "No limit" in the limit and available stat-cards and a progress-indicator at 0, with no division by zero. Test: Task 6, `renders no limit without a credit limit`.
2. An installment amount whose total is below the purchase total (negative interest) disables save and shows the reason; it never posts a negative `interest`. Test: Task 10, `rejects negative interest`.
3. A financing installment amount whose total is below `unpaid` previews a negative interest and disables submit. Test: Task 9, `disables submit on negative interest`.
4. A reference month renders in its own month in a timezone west of UTC (`2026-01` stays January). Test: Task 5, `formatReferenceMonth` row `UTC month boundary`.
5. A card with more statements than one page (`next_cursor` present) lists all of them and finds the current statement on the second page. Test: Task 6, `reads every statement page`.

## Spec ambiguities resolved

| Topic | Resolution |
|---|---|
| B2 plan status | Derived, no column: `cancelled` when a non-voided transaction links `cancellation_of` the origin; else `anticipated` when a non-voided one links `anticipation_of`; else `active`. |
| B2 `reversed` | `true` for every installment of a `cancelled` plan (M25 credits billed installments too, S14). Otherwise `true` when a non-voided `anticipation_of` transaction of the origin has a `credit` card posting on the installment's statement. Cancellation credits merge per statement (S14: 2026-12 holds 2/3 and the billed 1/3), so amount matching is not used. |
| B2 `amount` | Positive magnitude (negated charge posting), consistent with C8 display. `interest` omitted when zero. |
| B3 voided sources | A voided source transaction is excluded from `referenced_by`, matching `RefundedTotal`, which ignores voided postings. `referenced_by` is optional in the schema and present (possibly empty) only on `GET /transactions/{id}`. |
| B4 empty body | `required: [active]` makes the contract middleware answer 400 `invalid_request` with field `active` (`internal/platform/contract/contract.go`, `schemaViolation`). |
| Card figures source | The overview reads the card account through `GET /accounts/{id}` under `[...accountKeys.detail(a), "account"]`, so `transactionMutated` refreshes the available limit (S06); `accountsQuery` (`accountKeys.list`) is not invalidated by purchases. Debt = negated booked balance from `balanceQuery`. |
| Used share | `usedShare(debt, limit)` = `min(100, max(0, floor(debt × 100 / limit)))` on integers; 0 when there is no limit. |
| Last used payment source | `localStorage` key `equori.cards.payment-source` holds the account id; absent or no longer eligible → the first eligible account by name. |
| C12 form state | The purchase form reuses the transactions `formReducer` in split mode (`SplitEditor` with `minLines={1}`, `canUnsplit={false}`); `splits` = `state.split` lines as `{ account_id: categoryId, amount }`; the purchase total is `state.amount`. |
| Settings create forms | Billing rule, credit limit and card creation open in a `Dialog` (bottom `Drawer` at phone width); the Routes table defines no settings sub-route. |
| Billing rule in force | The version with the greatest `effective_from` ≤ the current month; credit limit in force: greatest `effective_from` ≤ today. |
| Reactivating a card | The inactive section offers "Reactivate" without confirmation; only deactivation confirms (C20). |
| Card panel composition | `web/src/app/transaction-route.tsx` holds one component rendering `<TransactionPage extension={CardTransactionPanel} />`; an inline component in `router.tsx` would break `react/no-multi-comp`. |

  EXISTS (SELECT 1 FROM ledger_link l JOIN ledger_transaction t ON t.id = l.from_transaction_id
