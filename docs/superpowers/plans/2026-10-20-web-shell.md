# Web Shell Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the authenticated application frame (`web/src/app/shell/`, `web/src/ui/`) with a new desktop shell (side navigation, command palette, account menu) and a new Android-first phone shell (top app bar, navigation bar, extended FAB, bottom sheet).

**Architecture:** One `AppShell` (Slotted) hosts both layouts so `AppShellMain` and the routed page keep their position in the React tree when the width crosses 1024 px. At 1024 px and above the `nav` region holds a `SideNavigation` column; below 1024 px the `banner` holds an own top app bar and the `footer` holds an own dock (navigation bar plus FAB). Destination data, the current-destination match and the entry action are shared by both layouts.

**Tech Stack:** React 19, TanStack Router 1.170, TanStack Query 5, `@slotted/react` 0.1.0-beta.5, Vitest + Testing Library + jsdom.

**Spec:** the brainstorming conversation of 2026-10-20 (no spec file). Decisions taken there: rewrite from zero, nothing reused from the current shell; desktop modelled on Linear and Monarch Money (side column, `Ctrl+K` palette, entry button with key `N`, account menu at the column foot, each page owns its header); phone modelled on Material 3 (navigation bar with Overview, Transactions, Cards, Accounts and More; More opens a bottom sheet with Goals, Admin, Settings, colour scheme, language, log out; FAB for a new transaction; top app bar that changes on scroll; edge to edge with safe-area insets).

## Global Constraints

- No new dependency (root `CLAUDE.md`, Code).
- Rules O1–O8 of `web/CLAUDE.md`: kebab-case files, one component per file, no JSX literal text (`useT()`), app CSS in `*.module.css` inside `@layer app`, reading only `var(--slotted-*)` application tokens (OE-01), never targeting `[data-ui]` or `[data-part]`.
- Own elements (top app bar, navigation bar, FAB, icons) carry a build-own-element comment naming the families read; they meet OE-02 (state order), OE-03 (focus ring tokens), OE-04 (`--slotted-target-min`, `--slotted-target-comfortable` under `pointer: coarse`).
- Every user-visible string exists in `catalog.en.ts` and `catalog.pt-BR.ts`.
- Breakpoint: `(min-width: 1024px)` is desktop; anything narrower is phone.
- Every transition reads the motion tokens (`--slotted-duration-*`, `--slotted-easing-*`) and collapses under `prefers-reduced-motion: reduce`.
- Slotted findings met during the work are reported in the final reply under `Slotted findings` (web/CLAUDE.md template).
- Commits only when the owner asks; the working tree carries the owner's own uncommitted work in `web/`.

## Review Focus

1. A deep link to a detail route (`/accounts/<id>`, `/transactions/<id>/correct`) on a phone: the back control goes to the parent destination, not out of the app, when there is no in-app history. Test in Task 4.
2. The `N` key while a field, a menu, the palette or a sheet holds focus does not open the entry. Test in Task 2.
3. Resizing across 1024 px keeps the routed page mounted (no remount, no lost page state). Test in Task 1.
4. The More tab reads as current on `/goals`, `/admin` and `/settings`, which have no tab of their own. Test in Task 5.
5. A tap on the current tab at its own route scrolls the page to the top instead of navigating. Test in Task 5.
