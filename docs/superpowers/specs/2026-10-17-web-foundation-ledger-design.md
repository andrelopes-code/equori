# Web track, sub-project 1: foundation and Ledger screens

- Date: 2026-10-17
- Branch: `feat/web-ledger`
- Depends on: `docs/superpowers/specs/2026-10-16-web-foundation-design.md` (toolchain, build, embedding), ADR 008 (web interface).

## Intent

The web interface is the only client of equori. This sub-project delivers the application foundation (theme, shell, routing, data, errors, i18n) and the Ledger screens: login, home, transactions, accounts and settings. Later sub-projects add screens on this foundation without changing it.

## Web track decomposition

| # | Sub-project | Scope |
|---|---|---|
| 1 | Foundation + Ledger | this spec |
| 2 | Cards | statements, installments, disputes, refunds, credit limits |
| 3 | Import and classification | file import, CSV profiles, categorization review, Pluggy (incl. opening Pluggy Connect from the UI) |
| 4 | Planning | budgets, commitments, projection |
| 5 | Investments and reports | holdings, trades, prices, reports |

Each sub-project has its own spec, plan and implementation cycle.

## Requirements

- R1: the UI uses the Slotted component library (`@slotted/react`, `@slotted/core`, `@slotted/theme`, `@slotted/themes`, exact version `0.1.0-beta.2`) with an equori theme built on its tokens and families.
- R2: every screen is fully usable on a phone, with phone-specific ergonomics (section 2).
- R3: the Slotted agent snippet (`dist/docs/AGENTS.snippet.md` of `@slotted/react`) is copied into the root `CLAUDE.md`, with `{{docsDir}}` resolved to `web/node_modules/@slotted/react/dist/docs`.
- R4: the code follows the organization rules O1–O8 (section 1).
- R5: the UI is available in pt-BR and en; number, currency and date formats follow the locale (N21).

## Section 2: theme, shell, responsive navigation

Theme:

- `extendTheme` on `@slotted/themes/default`, compiled with `slotted-build-theme` into `theme/equori.gen.css`, verified with `themeConformance` from `@slotted/theme/conformance`.
- Accent: teal. Intents tuned for money (section 3, tones).
- Scheme: dark by default; light and system selectable per device (localStorage); set through `data-slotted-scheme` on `<html>`.
- Density: `compact` at viewport width ≥ 1024 px; `comfortable` below, with touch targets ≥ 44 px; set through `data-slotted-density`.
- Font: the Slotted default. Any own font ships inside the binary (CSP `default-src 'self'`).
- Money uses `font-variant-numeric: tabular-nums`.
- CSS layers: `@layer slotted, app;`.

Navigation:

| Width | Navigation | "New transaction" action |
|---|---|---|
| phone < 600 px | `ui/bottom-bar`, 5 controls: Home, Transactions, New (centre, emphasized), Accounts, More | bar centre control |
| tablet 600–1023 px | side-navigation collapsed to an icon rail | primary button in page-header |
| desktop ≥ 1024 px | side-navigation expanded | primary button in page-header |

- Slotted has no bottom-navigation family; `ui/bottom-bar` is an own element (package skill `build-own-element`), limited to five controls (SC-05).
- "More" opens an action-sheet: Settings, Colour scheme, Language, Log out.
- Phone: `viewport-fit=cover` and `env(safe-area-inset-*)`; `100dvh`; sticky page-header with actions on the title line (LA-03); one scroller per page (LP-12).
- Create forms are routed pages (`/transactions/new`, FM-01). The system back gesture closes them. The draft persists in sessionStorage until save or discard.
- Inputs: currency-field with `inputmode="decimal"`; date-picker defaulting to today; entity-picker full-screen on phone with recently used items first.
- The submit button is pinned at the form bottom above the virtual keyboard (`visualViewport`).
- Web app manifest: `display: standalone`, icons, `theme-color`. No service worker; no offline mode.

## Section 3: Ledger screens

| Route | Content | Actions |
|---|---|---|
| `/login` | email, password | log in; invalid credentials show the Problem.code message |
| `/` Home | balance-sheet account balances grouped by kind (available, reserves, cards, loans) with base-currency totals; 5 recent transactions; "N uncategorized" shortcut | new transaction; open account or transaction |
| `/transactions` | grouped by date with sticky day headers; infinite scroll; URL filters: account or category (`account_id`), payee, tag, period, uncategorized, text (`q`, B1) | filter; open; new |
| `/transactions/new` | segmented Expense / Income / Transfer; amount, account, category, date, payee (created inline), tags; "Split" adds category lines and shows the remainder; "Advanced" opens a free postings editor | save; save and add another |
| `/transactions/:id` | amount, date, description, payee, tags, postings with status, origin, version; a voided transaction is struck through with its reason | correct (prefilled form, required reason, `expected_version`); recategorize (`/categorize`); void (dialog with reason); version history (timeline) |
| `/accounts` | tree by class: balance accounts with balance; income and expense categories | create; rename and move (PATCH); close (zero balance only) |
| `/accounts/:id` | booked and settled balance; 90-day daily balance chart (`/reports/balances`); the account's transactions (same list component) | new transaction with this account preselected; edit; close |
| `/settings` | base currency (locked after the first transaction, reason shown), institutions, payees, language, scheme | create institution and payee |

Rules:

- Row amount: with an account filter, the posting of that account; without one, the sum of postings on balance accounts. A transfer shows one side with a transfer icon.
- Tones: inflow uses the positive tone; outflow uses the neutral text tone. Red is reserved for negative balances and errors.
- Phone row: payee or description, category, amount on the first line; account and tags on the second line (LP-01). Filters open in a bottom drawer. Active filters show as removable tags under the header.
- A 409 on correction shows the current version and keeps the user draft for reapplying.
- Card accounts appear with their balance only.

Out of scope: statements, installments, disputes, reconciliation, attachments, foreign purchases, exchanges, trades.

Backend adjustments, delivered first, each with an apitest, the OpenAPI contract and `make gen`:

- B1: `GET /transactions?q=` searches description, payee name and posting memo (case-insensitive substring).
- B2: `GET /balances?date=&basis=` returns the balance of every balance-sheet account of the user in one call.

## Section 4: data, errors, i18n

- QueryClient: no retry on 4xx; 2 retries on network errors and 5xx. A 401 on any request clears the cache and redirects to `/login?redirect=<path>`.
- Session: the authenticated layout route loads `GET /me` in `beforeLoad`. Logout calls `DELETE /session` and clears the cache.
- Each mutation invalidates the keys it affects. A transaction mutation invalidates transaction lists, balances (B2) and the details of the affected accounts.
- Problems: `api/problem.ts` parses `application/problem+json` and looks up the catalog key `problem.<code>`, falling back to `title`. Entries of `errors` (`[{field, message}]`, ADR 004) attach to the form field named by `field`.
- Waiting states follow the package skill `waiting-states`: one skeleton per region; result-state for empty and error with retry; a toast on mutation success. A query change empties rows; a mutation keeps them (LP-06).
- Locale: default from `navigator.language` (`pt-*` → pt-BR, otherwise en), overridable in settings (localStorage). The locale sets `<html lang>` and the SlottedProvider catalogs (`PT_BR` from `@slotted/core/i18n/pt-BR`).
